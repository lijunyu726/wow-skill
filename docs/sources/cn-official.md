  - ⑪工程：three.js r186 + Vite，代码按职责拆模块，剧情不靠散落的计时器驱动，用实例化和分区剔除，留调试用的 URL 参数。
- 可复用的做法：

  - 要求在真实浏览器里截图验收，列出要查的画面和问题，没测的如实说明。

### Effort（Anthropic · Claude 开发者文档 · 页面未标注日期）
- 链接：https://platform.claude.com/docs/en/build-with-claude/effort
- 核对：2026-10-24 可访问（读取的是页面的 Markdown 版本）
- 类型：官方文档
- 质量：高。官方的参数说明，有各档定义，也有按模型给的推荐。
- 内容概括：
  - effort 控制回答时花多少 token，作用于全部输出：正文、工具调用及其参数、思考。它是行为信号，不是硬性预算。
  - 一共五档。max 是不限 token 的最高能力；xhigh 面向长程任务，表格里的典型用法是 30 分钟以上的 agent 和编码任务；high 是多数模型的默认；medium 是 Opus 5.5 和 Haiku 5.5 的默认；low 最省，适合简单任务和子代理。
  - Opus 5.5 专条：五档都支持；默认 medium，比 Opus 5 低一档，所以不写 effort 时会比以前少想一档。自适应思考始终开启、不能关，设成 disabled 会返回 400 错误，因此 effort 是控制推理量的主要手段。建议在自己的任务上做一次 effort 对比。
  - 和工具的关系：档位低时工具调用更少、更直接；档位高时会先讲计划，总结也更详细。
  - 最佳实践：显式设置；简单任务用 low；按自己的任务实测；按复杂度动态调整；依赖缓存的会话里不要改顶层 effort。
- 提示词要点：本页不讲提示词写法，参数写在请求的 `output_config.effort` 里。
- 可复用的做法：
  - 做作品先用 medium 跑通，确实需要再升 xhigh；30 分钟以上的长任务才考虑 xhigh。
  - 中途换档用逐条消息的 effort，避免缓存失效。
- 注意：
  - 页面没有发布日期。
  - 本页的五档里没有「Extra」。社区说的「Extra 档」是客户端里的叫法，在本页找不到对应的参数值。
  - 「xhigh 适合 30 分钟以上」是表格里的典型用例，不是硬性门槛。

### frontend-design · SKILL.md（Anthropic · GitHub anthropics/skills · 最近修改 2026-09-03）
- 链接：https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md
- 核对：2026-10-24 可访问（经 GitHub API 读取）

- 质量：高。这是官方维护的设计指导 skill，2026-09-03 刚针对「避免泛化的默认设计」更新过（提交 #1713），全文约 70 行，可以直接对照。
- 内容概括：
  - 角色设定：把自己当成一家设计工作室的设计总监，这家工作室以给每个客户独一无二的视觉身份著称。客户已经否掉了落俗、模板化的提案，花钱买的是鲜明的观点。
  - 立足题材：简报没说清题材时，先自己提出一个具体主题、受众和主要用途，再跟客户确认。独特的视觉选择来自题材所在的行业、材料和行话。
  - 设计原则：首屏用题材世界里最有代表性的东西开场，「大数字 + 小标签 + 渐变强调」是默认做法，不是最佳选择时不要用；字体承载个性，用一到两个字族；避开三种排版套路（标题里只强调一个词、标签全大写、内容上方加多余的小标签）；编号只在内容真是序列时用；非用户触发的动效要少，一个编排好的瞬间胜过满页淡入上滑。
  - 列出当下 AI 生成设计扎堆的五类特征：暖奶油底配衬线大标题和赤陶色强调；近黑底配单一亮色；报纸式版面；SaaS 卡片套件；与题材无关的模板装饰（全大写眉标、中点分隔、等宽数据标签、按钮文字后加箭头等）。这些是默认而不是选择；简报明确要哪种样子时，照简报做。
  - 流程分两遍：先出一份简短的设计方案（4–6 个命名的 hex 色、字体分工、带 ASCII 线框的版式概念、设计原则）；再对照简报检查，哪部分像任何类似页面都会做出的默认，就改掉并说明原因，之后才写代码。
  - 克制与自评：「Spend your boldness in one place」，只让一个元素成为记忆点，其余安静克制；守住质量底线（适配手机、键盘焦点可见、尊重减少动效、无障碍、配色和谐）；边做边截图自查，「a picture is worth 1000 tokens」；借香奈儿的话，出门前照照镜子，摘掉一件配饰；有地方记笔记，就记下这次试过什么。
  - 文案：从用户视角写，用主动语态，按钮写清点了会发生什么，报错不道歉、不含糊，空状态是邀请用户行动。
- 提示词要点（skill 本身的结构）：①身份加情境：设计总监，客户已否掉套路 ②题材落地 ③设计原则 ④反面清单：五类扎堆特征加三种排版套路 ⑤两遍流程：出方案、对照简报自查、再写代码 ⑥克制与截图自评 ⑦文案规范
- 可复用的做法：
  - 先出配色、字体、版式方案，对照简报找出泛化的部分，改完再动手。
  - 只在一处大胆，其余克制；交付前删掉一件装饰。
  - 把常见的 AI 设计特征写成反面清单；但简报明确要求的，照做。
